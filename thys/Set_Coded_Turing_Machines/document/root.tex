\title{Set-Coded Turing Machines in Isabelle/ZF}
\author{Tang Ziyi}
\maketitle

\begin{abstract}
We construct an explicit closed set-theoretic sentence for the halting of
a finite Turing machine on a finite input. For every transitive ZF set
model, satisfaction of the sentence is equivalent to external execution
reaching the final state. The construction uses set-coded machines,
finite execution witnesses, and formulas naming finite objects.
A primitive-recursive function constructs the sentence's natural-number
code from independent machine-code and unary-input arguments.
The library connects concrete program proofs to the existing Isabelle/ZF
model interfaces. Observational tape equality and worked clients support
reuse without unfolding the internal formulas.
\end{abstract}

\section{Result}
For a well-formed machine $P$ and finite symbol input $x$, let
$H(P,x)$ denote the constructed formula
$\mathit{halt\_sentence}(P,x)$. It is a sentence, with no free variables.
For every transitive ZF set model $M$,
\[
  M\models H(P,x)
  \quad\Longleftrightarrow\quad
  \mathrm{halts\_on}(P,x).
\]
Here halting means that a finite number of external machine steps
reaches the final state. The sentence is constructed from $P$ and $x$
alone and is the same for every model. A proof of a particular program's
halting or nonhalting therefore determines the truth of its sentence in
each such model. The result is conditional on the model premise and
asserts no model existence.

The public contract consists of
\theoremname{halt_sentence_type}, \theoremname{arity_halt_sentence}, and
\theoremname{sats_halt_sentence_iff}.
Their object premises are $P\in\mathit{tm\_machine}$ and
$x\in\mathit{list}(\mathit{symbol})$.
The predicate \theoremname{transitive_zf_model} requires a transitive set
satisfying the internalised ZF axiom set from
\theoremname{Internal_ZFC_Axioms}. This is a property of the model under
consideration, distinct from the ambient Isabelle/ZF logic.

There is also an effective syntax interface. For natural $e,n$, let
$P_e=\mathit{decode\_machine}(e)$ and
$x_n=\mathit{numeral\_input}(n)$, the list of $n$ ones. The certified
primitive-recursive constructor $F$ satisfies
\[
  F(e,n)=\ulcorner H(P_e,x_n)\urcorner.
\]
Thus a program and its input determine both a closed sentence and its
code. Section~\ref{sec:halting-codes} proves membership in the bundled
\texttt{prim\_rec} class and the application equation.
This is a certificate for numerical sentence construction. It does not
supply a compiler implementing arbitrary primitive-recursive functions
in the machine model.

\section{Proof}
\subsection{Finite witnesses}
A halting execution has a finite trace. If $P$ halts on $x$ at time $n$,
the canonical witness is
\[
  r=\lambda k\in n+1.\,\mathrm{steps}(P,\mathrm{initial\_config}(x),k).
\]
Each configuration is built from natural numbers and finite lists.
The model contains these objects and their ordered pairs. Finite induction
then places the entire trace in the model. The closure theorem
\theoremname{tm_finite_lambda_closed} requires membership of each value;
it does not require an external function to have been supplied internally.
\theoremname{transitive_zf_contains_trace} applies this argument to runs.

The explicit formula \theoremname{halt_fm} binds a natural time and a
witness set. It constrains the witness's value at time zero, each
successive transition, and the final state. The canonical trace satisfies
these conditions. Conversely, suppose an internal witness satisfies them.
Induction identifies each constrained value with the corresponding
external configuration. The one-step satisfaction theorem provides the
induction step. At the final time, the external machine must therefore
be in state zero.

These directions have different obligations. The external execution
supplies a finite function that belongs to the model. An arbitrary
internal witness need only satisfy the stated application constraints;
its entire set need not be a finite function. No interpretation of an
unbounded execution inside the model is assumed.

The shared lemmas \theoremname{trans_run_steps} and
\theoremname{trace_trans}, in the locale \texttt{M\_ZF1\_trans}, give
reconstruction and canonical transitions for arbitrary initial
configurations and outer formula environments. They isolate the
execution argument from a surrounding formula's variable layout.
The halting theorem and downstream output predicates use the same
lemmas. Section~\ref{sec:internal-halting} contains the explicit formula
and the proofs.

\subsection{Closed sentences and codes}
The formula \theoremname{halt_fm} has environment $[P,x]$.
Formulas naming natural numbers, instructions, and finite lists define
$P$ and $x$ uniquely. Binding these names yields $H(P,x)$ and discharges
both free variables. This construction uses the formula datatype of
\texttt{ZF-Constructible.Formula}~\cite{paulson-zf}.

\theoremname{Formula_Coding} assigns tags and paired natural-number
codes to the four formula constructors. Structural induction proves
injectivity. The primitive-recursive name constructors mirror the
syntactic construction. A bounded reverse traversal builds the name of
a decoded machine, whose list length is at most its code.
The resulting application equation identifies $F(e,n)$ with the code
of $H(P_e,x_n)$. Formula-code injectivity then identifies any well-formed
formula bearing that code, so no separate formula decoder is needed
for this contract.

The implementation of $F$ is
\theoremname{pr_machine_input_sentence_code}, applied to $[e,n]$.
The theorem \theoremname{sats_machine_input_sentence_code_iff} gives
satisfaction directly from that code. The unary constructor
\theoremname{pr_halt_sentence_code} is the diagonal instance $F(e,e)$.
These certificates use the Isabelle/ZF primitive-recursive function
class~\cite{szasz}.

\section{Use}
\subsection{Machine semantics}
A machine is a finite list of instructions over the symbols 0 and 1.
Each instruction contains an action and a next state. The actions write
0, write 1, move left, move right, or leave the tape unchanged. State 1
is initial and state 0 is final. The two entries for a positive state $q$
occur at indices $2(q-1)$ and $2(q-1)+1$. Missing entries enter the final
state without changing the tape. The final state is absorbing.

A configuration contains a state and two finite symbol lists. The left
list starts immediately left of the head, while the right list starts
at the scanned cell. Unrepresented cells are blank.
\theoremname{tm_step} and \theoremname{steps} specify one step and finite
iteration. The predicate \theoremname{halts_on} includes machine and
input validity. Theorem \theoremname{halts_on_iff_finite_run} supplies
the equivalent finite-function witness form.
For nonhalting proofs, \theoremname{not_halts_on_invariant} accepts an
initial, step-closed predicate that excludes the final state.

\subsection{Representation independence}
The lists $[1]$ and $[1,0,0]$ are distinct stored objects with equal
observed contents. The relations \theoremname{half_tape_eq},
\theoremname{tape_eq}, and \theoremname{config_eq} compare observations
at fixed positions relative to the head. They ignore trailing stored
blanks and preserve execution and halting. They do not identify head
shifts. Literal storage length remains a separate property.

The theorem \theoremname{sats_halt_sentence_half_tape_eq_iff} transfers
internal halting truth between observationally equal inputs. The
sentences may have different syntax and codes because they name
different lists. Their satisfaction agrees.

\subsection{A complete client}
\theoremname{Turing_Examples} defines a two-instruction machine that
scans a unary input and writes one at the first blank. Its loop invariant
gives the final configuration after $n+1$ steps. The head remains on
the newly written cell. The proof derives halting and transfers the
result to an input with an extra stored blank.

\theoremname{Turing_Halting_Examples} continues this same example.
The theorem \theoremname{scan_append_sentence} obtains internal truth
from the operational halting result.
The theorem \theoremname{scan_append_sentence_code} obtains truth of
any formula bearing the constructed code. Neither proof unfolds the
halting formula, the finite-object names, or the numerical constructor.
The operational example can be imported without model theory or coding.

\section{Sources and scope}
The instruction-list and two-list tape design follows the Isabelle/HOL
development of Xu, Zhang, and Urban~\cite{xu-zhang-urban} and its AFP
entry \emph{Universal Turing Machine}~\cite{afp-utm}. The representation
uses the unshifted \texttt{tprog0} convention, with natural-number
actions and symbols and no program-offset parameter.
Here machines and finite runs are sets whose membership in a model
can be proved in the same logic as the satisfaction statements.

Closure and satisfaction use the AFP model infrastructure
\cite{afp-models}. The \texttt{Independence\_CH} entry supplies the
locale and full-ZF interpretation in
\theoremname{ZF_Trans_Interpretations}~\cite{afp-ch}.
The proofs apply in the weaker locale \texttt{M\_ZF1\_trans}, which
assumes transitivity, Zermelo set theory, and four specified replacement
instances. The full-ZF results interpret this locale. No minimality of
these assumptions is claimed. No CH independence result or choice
assumption is used by the halting interface.

The underlying absoluteness method is classical~\cite[Chapter~12]{jech}.
The contribution is the explicit formula, its effective closed instances,
and their verified connection to concrete machine execution.
The semantic interface accepts all finite symbol inputs; the numerical
constructor uses unary inputs. Machine decoding normalises invalid
instruction fields and is total on natural numbers. Encoding and then
decoding a valid machine recovers it, while arbitrary machine codes need
not be unique.
