3 Mathematical and interface assessments

3.1 The mathematical assessment recommends acceptance within the declared
scope. The independent contribution is a proved connection between concrete
set coded execution, actual first order satisfaction in transitive models,
and primitive recursive construction of closed sentence codes. The
contribution is not the classical halting argument or CH independence in
isolation. The satisfaction theorem handles arbitrary typed machines and
finite inputs, so the interface extends beyond the final self input family.

3.2 The effective construction is substantive. Canonical finite traces enter
the model through closure proofs, and induction recovers an external run
from the required applications of an internal witness. Finite names then
bind both parameters. On the syntax side, a bounded reverse traversal of a
machine code constructs its name code through PREC. Exact application
equations identify the resulting numbers with actual formula codes. The
construction does not query halting or invariance as an oracle.

3.3 The interface assessment recommends minor revision. External users can
obtain the two explicit PR witnesses, their class membership, their exact
outputs, and a reduction relation with composition. Formula constructor
operations support new concrete sentence families. A complete decoder or
general compiler is not needed for these interfaces. The current direct CH
disagreement premise adequately separates effective construction from the
countable model existence argument.

3.4 The model premise is genuine. Invariance ranges over all transitive ZFC
set models. A countable transitive model supplies two CH disagreement
witnesses through the existing AFP results. When no such models exist,
closed sentence invariance is vacuous. The direct noninvariance premise and
the CTM version both exclude the case that would invalidate the reductions.

3.5 The source hardness and target reductions must retain their separate
contracts. K is undecidable under the local tm_decidable definition. The two
maps belong to the Isabelle/ZF prim_rec class. The entry does not prove the
general connection between those two computation interfaces. Its results
therefore do not establish machine undecidability of the complete target I,
the arithmetic truth reduction, or the complete EPQ conclusion. The current
scope statement observes this boundary.

3.6 The comparison was limited to directly related formal developments.
Universal Turing Machine supplies a broader computability development in
Isabelle/HOL. Transitive Models of Fragments of ZFC supplies model closure,
relativization, and satisfaction infrastructure. Independence_CH supplies
the model disagreement construction. This manuscript provides a concrete
ZF machine instance and effective syntax connecting those kinds of objects.
No exhaustive literature or archive search established priority. A new
classical theorem or first formalisation claim is not supported by this
review. The choice of ZF is justified by the need to treat machine data,
finite traces, formulas, and model satisfaction as related set objects.

4 Consolidated decision

4.1 MINOR REVISION. No additional mathematical theorem is required by this
review. The manuscript has a coherent, independently closed formal scope
and a reason to be considered as a reusable AFP contribution. This is the
internal reviewer's judgment. Acceptance remains a decision for AFP editors
and their appointed referees.

4.2 R1, required clarification. In submission/document/root.tex, define the
ordinary unary notation f_plus and f_minus by evaluating the formal functions
pr_invariance_positive and pr_invariance_negative on singleton lists.
The formal prim_rec functions have domain list(nat). The present unary
notation is inferable but its convention is not stated. One sentence is
sufficient. No wrapper function or new theorem is needed. R1 remains open
in the fixed manuscript.

4.3 C1, optional subtraction. Turing_CH contains the older halting_sentence
locale, and Turing_Halting_Sentences interprets it for blank input. Searches
of the maintained theories found this branch used only within those two
files. It is discharged correctly and is not a proof gap. Removing it from
the submission would remove an earlier conditional interface and a side
result that do not participate in the main effective reduction. Retaining
it as an expressly identified compatibility interface is also defensible.

4.4 C2, optional dependency refinement. The closed naming theorem does not
mathematically require CH. Its containing theory nevertheless imports
Turing_CH and Turing_Rejection. Consequently, importing that interface also
imports forcing and diagonalisation material. Moving the naming definitions
and satisfaction theorem into the existing Turing_Halting_Formula theory
would improve reuse without adding a file. This is a module boundary
improvement, not a condition for correctness or a demand for new mathematics.

4.5 The recommendation is to resolve R1 and then preserve the current
mathematical boundary. A compiler, arbitrary arithmetic translation, oracle
machines, target complexity classification, or a general model class would
change the scope. They are not substitutes for closing this review.
