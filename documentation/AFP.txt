AFP CANDIDATE

1 THEOREM AND BOUNDARY

Set_Coded_Halting_Invariance_ZF constructs an explicit internal halting
formula for set-coded Turing machines and proves its satisfaction theorem
in every transitive ZF set model. It closes that formula by naming the
machine and input. The proofs are established directly in M_ZF1_trans,
which requires transitivity, Zermelo set theory, and four replacement
instances. The ZF versions remain corollaries. Choice is not required.

The entry then constructs two primitive-recursive many-one reductions from
self-input halting and its complement to the natural-number codes of
closed sentences invariant across all transitive ZFC set models. The direct
semantic premise is that CH is not invariant. A countable transitive ZFC
set model supplies this premise through Independence_CH. The target
quantifies over all transitive ZFC set models, not only the countable ones.
Both reductions instantiate pr_reduces_invariance. This general interface
requires a uniformly expressed sentence family with primitive-recursive
codes and a fixed closed sentence on which the models disagree.

The source halting set is proved undecidable in the defined machine model.
The reducers are certified in Isabelle/ZF's prim_rec class and evaluated on
singleton lists. The entry does not establish closure of machine decidability
under arbitrary primitive-recursive reductions. It therefore does not claim
machine undecidability of the full target set, a general machine compiler,
or the EPQ arithmetic-truth reduction.

2 SOURCE AND EXPORT

The maintained candidate source is thys/Set_Coded_Halting_Invariance_ZF.
Its ROOT declares the nineteen theories and the proof document. The same
ROOT and sources are copied unchanged into the archive. The repository and
archive therefore use the same session and qualified theory names.
Research sessions extend that public interface.

The parent is Independence_CH. ZF-Induct supplies the primitive-recursive
function class. The declared timeout is 300 seconds. The archive includes
the proof document, its LuaLaTeX convergence script, and the repository
license. No separate computation entry is required.

The numeric evaluator, tape observation, bounded workspace, concrete
programs, and arithmetic extensions remain outside this candidate.
The exporter normalizes archive member order, permissions, ownership, and
timestamps. In the same Python environment, unchanged candidate contents
produce the same archive bytes. Each verification record shall identify
its source revision and archive checksum.

3 VERIFICATION

Use Isabelle2025-2, AFP 2026-02-06, and LuaLaTeX. documentation/BUILD.txt
gives the environment, export, proof, document, and style commands.
The exported archive is the acceptance target. Its proof build shall use
the declared ROOT timeout without an override.

Checks require a successful proof build, the maintained proof-dependency
check, both document variants with converged references and no overfull
boxes, and effective AFP mandatory style checking. The submission document
contains no CI instrumentation. The PDF checker compiles a separate copy
of generated LaTeX sources and requires its text and geometry to match the
unmodified PDF. It then checks the final compiler log and text bounds.

The pinned linter receives the maintained Isabelle2025-2 compatibility
patch. Clean and deliberately invalid controls verify that it parses commands
and detects the expected violations. An empty report without coverage and
control evidence is insufficient.

CI also checks all five maintained sessions and the independent computation
fragment. It retains the source revision, archive, documents, style reports,
controls, and build logs. Historical reports record their original tools
and revisions. A later correction does not retroactively validate their
evidence.

4 FORMAL CONTRIBUTION

The classical inputs are halting diagonalisation, absoluteness for
transitive models, and the independence of CH. The formal contribution is
the explicit connection from set-coded execution through internal
satisfaction and primitive-recursive sentence construction to invariance.
No claim of a new classical theorem or priority is made.

The entry is a candidate. Successful repository checks do not establish AFP
acceptance. Submission requires the project owner's explicit authorization,
reviewed author and contact metadata, and a maintenance commitment. A GitHub
merge, tag, or branch deletion is not an AFP submission requirement.
