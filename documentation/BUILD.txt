REPRODUCTION

1 ENVIRONMENT

The supported release is Isabelle2025-2. The candidate and research sessions
use the AFP snapshot dated 6 February 2026. The independent computation
check uses only Isabelle/ZF and bundled ZF-Induct. LuaLaTeX is required for
the PDF. Python 3 is required for repository checks and export. Poppler's
pdftotext is required for the PDF layout check.

https://isabelle.in.tum.de/website-Isabelle2025-2/
https://isa-afp.org/release/afp-2026-02-06.tar.gz

Run commands from the repository root with Isabelle on the executable search
path. Register the AFP theory directory using its actual absolute path.

    isabelle components -u /absolute/path/to/afp-2026-02-06/thys

2 MAINTAINED SESSIONS

ROOTS locates the candidate and five research sessions under thys. The
candidate is Set_Coded_Turing_Machines. The research sessions are
Turing_Invariance, Turing_Computation_Extensions, Turing_Machines_ZF, Turing_Models, and
Turing_Absoluteness.

    isabelle build -v -c -j 1 -o threads=2 -D .

This command exercises the timeouts declared in each ROOT. A diagnostic
timeout override shall be recorded as an override and shall not replace
the acceptance build. A successful build returns exit status 0. A build
without -c may reuse unchanged session products.

The independent computation fragment can be checked before registering AFP.
The script generates a temporary session from its seven maintained sources
and checks them over Isabelle/ZF and ZF-Induct. The temporary session is a
verification target, not another maintained public theory namespace.

    python3 scripts/check_computation.py --isabelle /absolute/path/to/isabelle --directory output/computation-check

3 REPOSITORY SOURCE CHECKS

The source check validates document references, theory membership, session
boundaries, and selected prohibited proof commands. It is not a proof check.

    python3 scripts/check_repository.py
    git diff --check

4 CANDIDATE ARCHIVE

thys/Set_Coded_Turing_Machines/ROOT is the single maintained and
exported manifest. Its parent is Independence_CH. The declared timeout is
300 seconds. The acceptance command does not override that value.

    bash scripts/package-afp-entry.sh
    mkdir -p output/afp-entry
    tar -xzf output/Set_Coded_Turing_Machines.tar.gz -C output/afp-entry
    isabelle build -v -b -c -j 1 -o threads=2 -D output/afp-entry/Set_Coded_Turing_Machines

The exporter copies the candidate ROOT, seventeen theories, and document
sources unchanged. It normalizes archive member order, permissions,
ownership, and timestamps. In the same Python environment, unchanged
candidate contents produce the same archive bytes.

5 PROOFS AND DOCUMENTS

The saved candidate heap supports the maintained dependency check.

    isabelle ML_process -d output/afp-entry/Set_Coded_Turing_Machines -l Set_Coded_Turing_Machines -f scripts/check_submission_proofs.ML

This check inspects the public endpoints for undischarged hypotheses.
It collects named facts from all seventeen canonical theories and checks
their proof closure for oracle dependencies. Explicit premises in theorem
statements remain premises.

Build both document variants with LuaLaTeX installed.

    isabelle build -v -b -c -j 1 -o threads=2 -o browser_info -o document=pdf -o 'document_variants=document:outline=/proof,/ML' -o "document_output=$PWD/output/afp-document" -D output/afp-entry/Set_Coded_Turing_Machines

The document build repeats LuaLaTeX until the auxiliary, contents, and
bookmark files stop changing. It fails if they do not stabilize within
six passes. Isabelle2025-2's default engine uses fixed compilation passes
and does not check convergence. document_output retains the unmodified
PDFs and generated LaTeX sources separately for each variant.

The layout checker uses fresh verification directories.

    python3 scripts/check_proof_document.py --pdf output/afp-document/document.pdf --sources output/afp-document/document --qa-dir output/afp-document-qa/document --isabelle /absolute/path/to/isabelle
    python3 scripts/check_proof_document.py --pdf output/afp-document/outline.pdf --sources output/afp-document/outline --qa-dir output/afp-document-qa/outline --isabelle /absolute/path/to/isabelle

The checker instruments and compiles only copies of the generated LaTeX
sources. The original candidate, source output, and PDFs remain unchanged.
The copy's extracted text, page dimensions, and word coordinates shall
match the original PDF. The checker then requires nonempty text within the
horizontal text bounds and rejects overfull boxes, unresolved references,
and rerun warnings in the final log. Both variants shall also have correct
contents references. A proof build without document=pdf does not check
these conditions.

6 AFP STYLE CHECKS

The pinned upstream linter revision is
c9983adc5c51a6455f702bb58c9f960d425a2af3. Its unmodified parser does not
reliably process Isabelle2025-2 exported command-range wrappers. An empty
report from that unpatched version does not establish effective checking.

The maintained compatibility patch handles these wrappers, rejects absent
parsed commands, and reports command coverage. Apply it to a fresh extraction
of the pinned revision before registering the component.

    python3 scripts/patch_isabelle_linter.py /absolute/path/to/isabelle-linter-c9983adc5c51a6455f702bb58c9f960d425a2af3
    isabelle components -u /absolute/path/to/isabelle-linter-c9983adc5c51a6455f702bb58c9f960d425a2af3/linter_base
    python3 scripts/check_linter_controls.py --isabelle /absolute/path/to/isabelle --output output/linter-controls
    isabelle lint -v -j 1 -o threads=2 -o lint_bundles=afp_mandatory -f error -O output/afp-lint.txt -D output/afp-entry/Set_Coded_Turing_Machines

The controls require a clean named lemma to pass, an unfinished proof to be
rejected, and an attribute on an unnamed lemma to be rejected. They also
require nonzero parsed-command coverage. Deliberate violations are created
only in temporary control sessions. Their logs and results.json provide the
control evidence. They are not candidate theories.

Style acceptance requires successful controls, nonzero command coverage in
the entry, and no mandatory findings. It does not replace mathematical review.

https://github.com/isabelle-prover/isabelle-linter

7 CONTINUOUS INTEGRATION

.github/workflows/isabelle.yml checks repository sources, the independent
computation fragment before AFP registration, all five maintained sessions,
the unmodified exported candidate, document variants and layout, proof
dependencies, linter controls, and AFP mandatory findings. Acceptance builds
use the ROOT timeouts. Artifacts retain the source revision, archive,
documents, style reports, and verification logs.

applies the maintained linter compatibility patch. It does not redistribute
the external distributions in the source repository.
